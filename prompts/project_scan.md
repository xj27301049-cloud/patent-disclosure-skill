# 全项目材料扫描

## 目标

提取可追溯的设计事实、版本差异、接口和公开风险，为申请文件提供证据底座。扫描结果进入 `design_evidence_ledger.md`，不得直接跳到“创新点”。

## 扫描范围与顺序

1. 本案最新结构说明、三维图、工程图、流程和动作说明；
2. 已提交相关申请及其权利要求；
3. 同批未提交案件，特别是上下游接口案和系统案；
4. 旧版本、否定方案、评审记录、计算、仿真和试验记录；
5. 销售、投标、客户交流、展会、论文、视频等公开线索。

大目录先用文件列表和全文搜索定位，再精读。记录文件名、版本/日期、页码/章节/附图/段落；仅记录文件名不算完成溯源。

## 文件处理

- `.docx/.pptx`：使用 `tools/docx_to_md.py` 或 `tools/pptx_to_md.py` 转为 Markdown 后读取。
- `.doc/.ppt`：工具不能直接解析时，要求另存为 OOXML；若已有可核验的文本抽取工具可使用，但记录局限。
- PDF或扫描件：提取全文；承载结构关系的附图必须查看。
- 图片：只有当结构关系未被文字充分表达、或图文可能冲突时才逐图核对。
- 代码/控制逻辑：只在其构成申请方案或解释动作链时扫描。

工具失败时记录失败原因并采用可核验替代方案；不得假称已扫描。

## 必须抽取

- 术语与部件编号；
- 部件位置、连接、约束、配合和运动自由度；
- 起始、过渡、终止状态及完整动作循环；
- 上下游输入/输出状态和接口；
- 当前主方案、并列替代方案、待选方案、已否定方案；
- 设计值、仿真值、试验值的来源；
- 同族共同结构和各案区别结构；
- 材料间的版本、编号、动作和效果冲突；
- 计划申请日及任何可能公开日期。

## 扫描门禁

至少形成：

1. 材料与版本清单；
2. `DF/DV/EV/U/X` 台账摘要；
3. 术语和部件映射；
4. 完整动作链；
5. 接口与专利族关系；
6. 冲突清单；
7. 公开时间线；
8. 仅会改变申请边界、可实施性或独权的待确认问题。

核心位置、配合或动作链缺失时触发 G1。样机、节拍或寿命数据缺失本身不触发 G1。
