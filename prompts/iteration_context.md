# 申请文件迭代上下文

## 路由

| 用户意图 | 下一文件 |
|---|---|
| 加入新材料、替代方案、附图或测试结果 | `merger.md` |
| 指出事实、结构、权利要求、编号或表述错误 | `correction_handler.md` |
| 改变保护重点或专利族边界 | `correction_handler.md`，并重跑受影响的 Step 3–7 |
| 收到审查意见 | 先重建引证文献与特征映射，再决定争辩、修改或分案 |

## 必读输入

- 当前基准申请文件；
- 本轮新增材料或用户纠正；
- 设计证据台账；
- 特征—说明书支持表；
- 检索/攻击矩阵；
- 专利族边界矩阵。

缺少工作底稿时，对受影响内容补建最小底稿，不要求无关部分从头重做。

## 联动规则

- 改权利要求：同步检查说明书、发明内容、摘要和附图；
- 改实施方式：反查权利要求是否仍覆盖及是否引入新内容；
- 改事实状态：更新 `DF/DV/EV/U/X`；
- 改必要特征、技术问题或效果：重跑相关检索、组合攻击和删除测试；
- 改专利族边界：同步检查相邻案件；
- 新增样机结果：只能支持原已公开内容；新结构不得倒灌为原申请日内容。

## 版本

默认另存：

`{案件名称}_{文件类型}_{YYYYMMDDHHmmss}.md/.docx`

保留上一版。维护 `申请文件修订记录.md`，记录时间、用户意图、变更范围、事实状态变化、受影响权利要求、检索/边界变化、交付文件和剩余风险。
