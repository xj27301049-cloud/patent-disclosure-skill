# 设计证据与验证状态台账

## 状态

| 标记 | 含义 | 可进入申请文件 |
|---|---|---|
| DF | 已由图纸、材料或用户确认的冻结设计事实 | 可进入权利要求和实施方式 |
| DV | 可由结构关系直接推导的作用或预期效果 | 可谨慎写为“能够/可使”，不得写成实测结论 |
| EV | 已由样机、仿真、计算或试验验证 | 可写明验证方式；仅有数据时才写具体性能 |
| U | 缺失或待选择 | 不得写成唯一方案或独权必要事实 |
| X | 材料、图纸或陈述冲突 | 关闭前不得据此定稿 |

## 每项字段

- 技术命题；
- 状态及证据类型；
- 文件、页码、附图或用户确认；
- 部件位置、连接/配合、动作和状态变化；
- 所属方案版本；
- 可支持的权利要求层级；
- 是否依赖样机验证；
- 失败时影响哪些权利要求；
- 待补替代方案或参数范围。

## 样机前专项检查

1. 图纸能否确定装配关系和运动自由度？
2. 动作是否存在干涉、死锁、无承接位置或先后矛盾？
3. 数量、尺寸和速度是结构限制、设计选择还是目标值？
4. “保持、识别、防错、兼容、同步”分别由什么结构实现？
5. 故障检测不是核心发明点时，可列为补强项；若权利要求依赖其闭环，则必须公开实现方式。
6. 是否存在至少一种可实施方案，以及支撑上位概括的合理替代方式？

## 禁止

- 把“拟采用”“理论上”“目标”升级为 DF；
- 因没有样机把所有结构降为 U；
- 把预期节拍、成功率、兼容率或可靠性写成 EV；
- 用效果描述填补缺失的结构关系。
